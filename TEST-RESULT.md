# Verification Record — v0.14.0

`npm test` passed with 162 tests and no failures in the source tree (151 pre-existing tests plus 11 new data-reshaping tests). Every JavaScript module under `src/` and the new test files passed `node --check`; `npm start` completed and printed the v0.1–v0.13 example output followed by the new v0.14 pivot, melt, and crosstab sections against the loaded CSV. `git diff --check` reported no whitespace errors.

The v0.14.0 regressions cover long-to-wide pivoting with duplicate-cell aggregation (the roadmap's exact example shape), the aggregation catalog in pivot cells including `quantile` with `q` and `count`, `fillValue` substitution for missing combinations, null pivot keys becoming their own `null` column, pivot validation (missing index/columns/values, unknown columns, unsupported aggregations, index/columns collision, unknown options), wide-to-long melting with the roadmap example shape, `valueVars` complement defaulting, null value preservation, id/value overlap and output-name-uniqueness errors, crosstab counts with totals row/column (grand total 4, per-row/per-column sums), row/column/total percentage modes with defined totals behavior (percent-of-total rows keep raw counts; grand-total cell is 1), values-column aggregation with percentage restrictions, transpose with label column, explode over arrays/empty arrays/nulls/scalars with element-order preservation, composition with the analysis, join, and window APIs (analyze/filter/orderBy/limit on pivoted output, innerJoin on pivot results, cumulativeSum on wide form, melt round-trips), source immutability across all five operations, empty-dataset results for every operation, and reshaping lineage (`pivot`, `melt`, `crosstab`, `transpose`, `explode`).

Reshaping operations are exported from the package root and `numeriq/reshape`, with TypeScript declarations for the reshape API in `index.d.ts`. `stack()`/`unstack()` are intentionally not provided (`melt`/`pivot` fill those roles) and `rename()`/`reorderColumns()` have existed since v0.1.0, per the roadmap's "only implement operations that fit the existing architecture cleanly" guidance. The v0.15.0 data-lineage milestone is deferred as documented in the README roadmap.
